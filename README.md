# AgentOps Harness · 可信多智能体编排与验证平台

> **一句话大白话**：这是一个给电商卖家用的「**AI 团队开店参谋 + 防亏本模拟沙盘**」。你把进货价、运费和同行售价丢进去，几个不同分工的 AI（算成本的、看市场的、找厂家砍价的、审风险的）会先开会算账、互相挑刺、自动把不划算的广告费调低，最后让你拍板上不上架，还可以连续模拟 8 个回合的突发断供和价格战。

## 一分钟大白话看懂本项目（新手必读）

打开网页后顶部有 **3 个标签页**，分别干三件事：

1. **1. 单品多维会签台（算单品能不能上架）**：
   - 把某件商品的采购价、快递费、同行价填进去，AI 团队分工算出「**保本底价**」和「**稳价 / 跟价 / 冲量**」3 套定价方案。
   - 如果广告费过高或活动打折会亏本，系统会自动调参重算（最多改 2 轮），最后停下来等你（掌柜）点「拍板通过」或「驳回」。
2. **2. 8回合动态市场与供应链博弈（模拟网店连续经营）**：
   - 模拟一家同时卖「茶叶礼盒（tea）」和「坚果零食（snack）」的网店连跑 8 个回合，专门测试两种常见突发状况：
     - **主供应商断供**：主力厂家没货时，自动唤醒谈判流程找备用厂家砍价（最多谈 3 轮），并且自动检查话术有没有说漏心理底价。
     - **竞品恶性价格战**：同行腰斩降价时，先算跟风降价或加投流是不是多卖多亏；如果倒贴钱，直接批 0 元预算。
   - 每一回合的账都会锁进防篡改指纹账本，你可以亲自点「尝试重做/篡改」验证系统如何拒绝事后改账。
3. **3. 多Agent vs 单Agent 评测竞技场（4 种 AI 工作模式跑分对比）**：
   - 用同一批 **12 道上架难题** 和 **8 回合经营实战**，同屏对比 4 种模式谁更稳、赚得更多：
     - `rule`（静态规则）：纯死板公式算账，不会变通。
     - `single-agent`（单 Agent）：1 个全能 AI 单干，没人挑刺，容易漏看风险。
     - `collab-no-review`（无审多 Agent）：多 AI 分工，但砍掉了风控审核和自动改错。
     - `collab-with-review`（完整多 Agent 会签）：本平台完整方案——分工 + 交叉质询 + 风控把关 + 自动改错。

### 常见专业词 → 大白话速查表

| 页面里看到的专业词 | 大白话是什么意思 |
| --- | --- |
| **会签 / 掌柜拍板** | 多个 AI 角色先各自算账挑刺，最后汇总交给你做最终决定 |
| **保本红线（保本价）** | 不赚不亏的最低卖价（算进了进货、快递、包材、抽成和退货亏损），低于它卖一单亏一单 |
| **p10 / p50 / p90 利润** | 模拟未来 30 天 200 次市场波动：p50 是正常行情赚多少，p10 是最倒霉的 10% 行情下还能剩多少（用来防亏底） |
| **Self-Loop / 经济修正** | 算出来超预算或亏本时，自动把广告费调低或换成更稳妥的方案重算一遍 |
| **规则 Harness** | 未填大模型 API Key 时，完全用本地固定数学公式和规则算账，不瞎编数字 |
| **底价脱敏校验 (screenTalk)** | 跟供应商砍价前检查话术，防止把自己的最高心理底价说漏嘴 |
| **负边际归零拦截** | 多花钱降价或投流反而多卖多亏时，强行把预算砍成 0 元 |
| **版本热升级 (`1.0.0 → 1.0.1`)** | 吃一堑长一智：第 1 回合跑完总结市场反馈，第 2 回合起自动升级定价策略继续跑 |
| **SHA-256 指纹 / 封存** | 防篡改电子封条，保证同一份输入重跑的结果分毫不差、历史记录不可偷改 |

---

面向「复杂行业任务的 Agent 编排」：定义 Agent 团队，把任务拆成带依赖、并行、条件与循环的工作流，由调度器按能力画像、运行负载和历史失败动态分配，再经过验证、自我循环修正和人工门，最后封存一条可回放的事件链。

演示场景是**商品上架评审**：从商品链接或分享文案 + 经营数字，跑出一条完整的 10 角色协作链路（保留 7 角色兼容模式），产出定价、风险与上架建议。

## 平台做了什么

| 赛题要求的能力 | 平台里的实现 |
| --- | --- |
| Agent 团队定义 | `src/templates/agentops/catalog.ts`：10 个 Agent，各有角色、版本、能力画像、工具集与调用预算 |
| 工作流编排 | 同一文件里的 `DEFAULT_WORKFLOW`：顺序、并行（成本/市场）、条件分支、Self-Loop、人工门、最终验证、封存 |
| 动态调度 | `resolveAgent()` 按 `能力×负载×历史失败` 打分选择，并记录候选分数与理由 |
| 工具集成 | 9 个注册工具（链接解析、成本、保本价、三策略报价、30 天模拟、约束验证、文案、报告、知识库检索） |
| 多 Agent 协作 | 研究 → 成本 ∥ 市场 → 风控 →（失败回路）→ 文案 → 人审 → 报告 → 终检 |
| Self-Loop | 风控未通过时把验证结论反馈给调度器，调整假设后重跑受影响分支，最多 3 轮，每轮留痕 |
| 结果验证 | 逐项 verifier（保本价、目标毛利、p10 风险、证据边界、终检一致性），状态 pass / warn / fail |
| 可复现 | 每个事件带前序哈希成链，运行结束封存 SHA-256 指纹；同一输入重跑结果完全一致 |
| LLM 推理节点 | 文案节点可接 OpenAI-compatible 模型；模型输出必须通过长度与风险词校验，否则回退规则并记录 `llm.fallback` |

## 怎么跑

需要 Node.js 22 和 pnpm 10。

```bash
pnpm install
pnpm dev
```

- 界面：http://127.0.0.1:47322
- 接口：http://127.0.0.1:47321

在首页输入一段自然语言任务即可运行，例如：

> 分析这个拼多多商品是否值得上架：链接 + 分享文案。采购 16 元，包材 1.5 元，快递 6.5 元，目标毛利 30%，推广预算 30 元，可周转资金 300 元。

界面会实时给出：调度了哪个 Agent、为什么选它、调用了什么工具、验证通过与否、是否进入 Self-Loop、报告与指纹。

## 无链接资料与协作证据

商品还没上架时，可直接在「没有链接？按项填写」录入资料，也可写下已知信息后点「让助手问我」。助手先补齐商品名、进货成本、单件运费和同类参考价；核对其余试算假设后才开始评审。明确填写的零运费、包材、广告预算、日单量和周转资金会保留。

采购、定价、推广分别执行分析，交付每套报价的情景数值；市场报价责任人逐项回应质询，风控再裁决。界面显示各方执行次数、基准与压力 p10、毛利、未消除异议和裁决对照。压力情景仍是本地规则假设；未消除的失败项保持失败。旧的直接试算入口仍可使用，会明确展示演示假设。

## 模型配置（可选）

默认不需要任何密钥：调度、工具、验证、循环全部是本地确定性实现，方便复现演示。

要启用真实模型节点：

```bash
AGENTOPS_LLM_BASE_URL=http://localhost:11434/v1   # Ollama / vLLM / 任意兼容网关
AGENTOPS_LLM_MODEL=qwen2.5:7b
AGENTOPS_LLM_API_KEY=local
```

配好后，资料助手可让模型组织缺项问法（缺项判断仍由规则决定，失败或超时回退）；「文案」节点交给模型生成，输出先过校验（平台字数上限、极限词黑名单、JSON 结构），不合格就回退规则文案并留下 `llm.fallback` 事件。平台不会把规则结果伪装成模型推理。

```bash
pnpm lint && pnpm typecheck && pnpm test   # 120 个测试
pnpm e2e                                   # 自动启动隔离服务；先关闭占用同端口的 dev
```

## 几十秒看懂数字打哪来

```
一件成本 = 采购价 + 包材 + 快递 + 平台佣金 + 支付手续费 + 退货摊销
退货摊销 = 退货率 ×（来回运费 + 包材 + 商品折损）
保本价   = 一件成本 ÷（1 − 平台佣金率 − 支付费率）
单件净利 = 售价 − 一件成本 − 推广摊销
日订单量 = 竞品价下的市场日单量 ×（竞品价 ÷ 售价）^ 价格弹性 + 推广带来的单量
推广单量 = 日预算 ÷ 点击单价 × 转化率
```

30 天推演：每天的需求按 ±28% 随机波动，备货受周转金限制，回款按平台账期延后，跑 200 次取 p10 / p50 / p90。推荐方案按 p10（最差 10% 的情况）挑，不赌最好的一天。

## 目录

- `src/templates/agentops/`：**平台层**。`catalog.ts`（Agent 团队、工具注册表、工作流定义、调度打分）、`runner.ts`（执行、验证、Self-Loop、事件链与指纹）、`llm.ts`（模型节点提示词与输出校验）、`types.ts`（工作流节点、事件、产物类型）。
- `src/templates/intake/`：商品链接与分享文案解析，作为「研究 Agent」的工具。
- `src/templates/pricing/`：定价领域计算。`economics.ts` 成本与需求，`simulate.ts` 30 天现金流推演，`candidates.ts` 三套方案与风控检查，`copy.ts` 标题卖点，`platform.ts` 六个平台的默认费率与标题限制。
- `src/server/`：Hono 接口（`pricing-app.ts`）、Agent 运行存档（`agent-runs.ts`，存在 `.data/agent-runs/`）、本地方案存档（`plans.ts`）。
- `web/`：Vite + React + Tailwind 的 Agent 控制台。
- `src/engine/`、`src/templates/simshop/`、`src/server/app.ts`：更早的多 Agent 编排引擎、确定性沙盘和它的事件流接口，保留并带完整测试，作为回归基准与设计参考。

## 接口

```
POST /api/agentops/intake             评审前检查资料并追问缺项；不创建运行
GET  /api/agentops/catalog            Agent 团队、工具注册表、默认工作流
POST /api/agentops/runs               传 {task, autoApprove?, collaboration?, budgetCeiling?, modelReview?, retrieval?}，执行一次完整编排（支持 accept: text/event-stream 流式响应）
POST /api/agentops/runs/stream        同上，专用于 SSE 事件流返回
GET  /api/agentops/runs               运行列表
GET  /api/agentops/runs/:id           单次运行：调度、事件、验证、循环、产物、指纹
GET  /api/agentops/runs/:id/events    只取事件链与指纹

GET  /api/platforms                   平台预设：抽成、支付费、退货率、标题字数上限
POST /api/plans                       传一份商品输入，返回三套方案 + 过程 + 指纹
GET  /api/plans/:id/export.csv        导出价格表（带 BOM，Excel 直接开）
```

### 运行选项与安全排除说明

`POST /api/agentops/runs` 与 `POST /api/agentops/runs/stream` 支持以下可选字段（采用严格校验，未知字段直接返回 400 `bad-request`）：
- `collaboration`: 可选布尔值，是否启用多 Agent 协作工作流。
- `budgetCeiling`: 包含三项有界非负数值的预算上限对象 `{ maxTokens: number, maxToolCalls: number, timeoutMs: number }`（上限：`maxTokens` ≤ 1,000,000, `maxToolCalls` ≤ 10,000, `timeoutMs` ≤ 300,000）。超限或部分缺项将被拒绝。
- `modelReview`: 可选布尔值，是否在有模型配置时启用多模型审查会审。
- `retrieval`: 检索配置对象 `{ enabled: boolean, query: string, platform?: PlatformId, timeoutMs?: number }`。开启时仅允许调用受信任的进程内内置知识库（`knowledge.search`），`timeoutMs` ≤ 60,000。

**安全排除原则**：
- 禁止通过客户端请求指定或传入 MCP 协议命令（`protocols.mcp.command`）、Shell 指令或任何可执行程序；MCP 协议挂钩属于服务端受信配置。
- 禁止传入自定义 retriever 函数、URL、`baseUrl`、`apiKey`、`liveEndpoint` 或任何任意文件/内网地址（如 `file://`、`http://127.0.0.1/`）。
- 接口严格阻断对运行时 LLM 连接参数和设置存储的注入篡改。

## 边界（请务必知道）

- 本项目第三方依赖许可证与归属通告见 [NOTICE.md](./NOTICE.md)（仅供清单记录与归属通告，非正式法律意见）。
- 平台费率是常见参考值，各平台按类目浮动，请填你后台的实际扣点。
- 需求模型只用任务里给的市场日单量和价格弹性，不预测趋势、不保证销量；没给的数字会在报告里列为「演示假设」。
- 短链和动态商品页不会被假装解析；缺失字段进入待确认，不写成已抓取事实。
- 卖点模板句要换成你实拍实测能对上的话；标题别写「全网最低」「销量第一」。
- 运行指纹只能证明「同样输入得到同样事件链和结果」，不能证明市场会照着走。
- 默认运行使用确定性规则 Harness；未配置模型时，界面不会宣称存在模型推理。

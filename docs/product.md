# 掌柜台：从「沙盘演示」改成「能用的定价工具」

## 为什么改

原来的产品是 8 回合的虚拟小店沙盘：剧本、随机种子、模拟市场，跑完给一张好看的账本。它证明得了多 Agent 能协作，但对真正开店的人没有用——里面的茶和零食是假的，价格是剧本写死的。

改版只做一件事：**把输入换成老板的真实数字，输出换成能直接抄进后台的东西。**

## 保留了什么是真的

- 多角色分工：成本会计 / 定价参谋 / 风控审核 / 文案手，各有各的职责，不是同一个模型换个名字。
- 交叉验证：定价参谋出的价要过风控的 7 项检查；推广费吃掉太多毛利时会被退回修正一次，修正过程在界面上看得见。
- 可核对：每一步有哈希，方案有指纹。同样的输入永远算出同一份方案——老板第二次改价时可以比对「到底哪一版变了」。
- 锁定：定下来的价不能偷偷改，改价必须重新核算，留痕。

## 扔掉了什么

- 剧本（spring / supplycut / pricewar）和随机种子驱动的「剧情」。
- 虚构的茶饮与零食品类、虚构的供应商断供事件。
- 与真实决策无关的编排表演（把节点图、事件流直接甩给用户）。

## 数字是怎么来的

| 量 | 公式 | 为什么要这么算 |
| --- | --- | --- |
| 退货摊销 | 退货率 ×（来回运费 + 包材 + 商品折损） | 退货的钱不是「概率」，是实打实要出的两趟运费 |
| 保本价 | 一件成本 ÷（1 − 佣金率 − 支付费率） | 平台是按成交额抽成的，所以除数要减掉抽成 |
| 推广摊销 | 日预算 ÷ 当日总单量 | 单量越高，每单背的推广费越薄，这就是冲量价能成立的前提 |
| 需求 | 市场日单量 ×（竞品价 ÷ 售价）^ 弹性 + 推广单量 | 用老板自己填的竞品价和该价位的日单量做锚点，不凭空造流量 |
| 备货上限 | 周转金 ÷（采购价 + 包材） | 账期没到，钱压在平台里，卖得多反而可能断货 |
| 推荐口径 | 在毛利率达标且不为负的方案里，取 30 天 p10 最高 | 不赌最好的那天 |

## 三条硬规矩

1. **不编数据。** 没有抓取平台、没有假装有实时热销榜。市场日单量、竞品价、费率全部由用户填。
2. **不编承诺。** 卖点只从用户勾选的服务承诺和算出来的真实差价里生成；模板句标「需你确认」。
3. **不藏着算式。** 界面上能点开看到成本拆解、检查项、推荐理由；README 里把公式全写出来。

## 下一步能做的

- 多规格 SKU：一个链接下多个规格，分别算价。
- 竞品价带：填 3–5 个竞品价，自动找出价格带里的空档。
- 历史对比：同一件商品改价前后，方案指纹和利润区间的差异。
- 平台后台对接：目前是复制粘贴 + CSV，再往下需要各平台开放接口或浏览器插件。
